## Overview 

With DNS and DHCP running, this lab adds the file distribution layer. PXE boot uses two protocols for two distinct stages: TFTP delivers the bootloader and kernel during the firmware stage, while FTP serves the full installation media once the installer is running. I use FTP specifically because it integrates cleanly with [[Anaconda]], the Red Hat family installer..

In this lab I install `vsftpd` on Server 1, configure it for anonymous read-only access, then copy the full contents of both a CentOS 7.2 ISO and an AlmaLinux 9 ISO into the FTP directory. [[PXE Lab 4 - Configuring PXE Boot|Lab 4]] will reference these directories as the package source for network installations.

I also add a NAT adapter to Server 2 in this lab so it can reach the internet for package installs, and configure it as a DNF client pointing at Server 1's FTP as a local repository.

**What this lab adds to Server 1:**

```
Server 1 (192.168.56.106)
├── DNS  - named    (port 53)  - Lab 1
├── DHCP - dhcpd    (port 67)  - Lab 2
└── FTP  - vsftpd   (port 21)  - this lab

/var/ftp/pub/
├── centos72/       - CentOS 7.2 ISO contents (~4 GB)
└── almalinux9/     - AlmaLinux 9 ISO contents (~3 GB)
```

## Part 1 - Add a NAT Interface to Server 2

Server 2 currently only has the host-only adapter. Without a second adapter for internet access, it cannot install packages like `bind-utils` (which provides `dig`) from the internet. Adding a NAT adapter on Adapter 1 gives it internet access while keeping the host-only `enp0s8` interface for internal lab communication. 

*Should have done this at [[PXE Lab 2 - Configuring a DHCP Server#Part 2 - Create Server 2|Server 2 creation]]*
### Shut down Server 2

```bash
shutdown -h now
```

### Add the NAT adapter in VirtualBox

1. Select Server 2 - **Settings - Network**
2. Click the **Adapter 1** tab (Adapter 2 is already the host-only `enp0s8`)
3. Tick **Enable Network Adapter**
4. Set **Attached to:** `NAT`
5. Click **OK** and power Server 2 back on

Using Adapter 1 for NAT means it appears as `enp0s3` inside the VM, keeping the interface naming consistent with Server 1.

### Verify both interfaces are up on Server 2

```bash
ip a s
```

```
2: enp0s3: ... inet 10.0.2.15/24 ...    (NAT, internet access)
3: enp0s8: ... inet 192.168.56.120/24 ... (host-only, DHCP from Server 1)
```

### Prevent the NAT interface from overriding DNS

The NAT interface gets DNS from VirtualBox (`10.0.2.3`) via DHCP. Without suppressing this, NetworkManager would overwrite `/etc/resolv.conf` and break resolution of `example.vm`.

```bash
nmcli connection modify enp0s3 ipv4.ignore-auto-dns yes
nmcli connection down enp0s3 && nmcli connection up enp0s3
```

Verify DNS still points to Server 1:

```bash
cat /etc/resolv.conf
```

```
# Generated by NetworkManager
search example.vm
nameserver 192.168.56.106
```

Test DNS resolution and internet access:

```bash
ping server1.example.vm
ping 8.8.8.8
```

```
PING server1.example.vm (192.168.56.106): 64 bytes from 192.168.56.106: ttl=64 time=0.966 ms
PING 8.8.8.8: 64 bytes from 8.8.8.8: ttl=113 time=23.0 ms
```

Both succeed - Server 2 now resolves internal hostnames via Server 1 and reaches the internet via the NAT adapter.

## Part 3 - Configure vsftpd

The default vsftpd configuration allows far more than needed for this lab. I replace it with a minimal configuration focused on anonymous read-only access over IPv4.

```bash
vi /etc/vsftpd/vsftpd.conf
```

Replace the contents with:

```
anonymous_enable=YES
local_enable=NO
write_enable=NO
local_umask=022
dirmessage_enable=YES
xferlog_enable=YES
connect_from_port_20=YES
xferlog_std_format=YES
listen=YES
listen_ipv6=NO
pam_service_name=vsftpd
userlist_enable=YES
anon_world_readable_only=YES
```

| Setting | Meaning |
|---------|---------|
| `anonymous_enable=YES` | Allow anonymous logins without a password |
| `local_enable=NO` | Block system user logins over FTP |
| `write_enable=NO` | No uploads or directory creation allowed |
| `listen=YES` | Run in standalone mode on IPv4 |
| `listen_ipv6=NO` | Disable the IPv6 listener |
| `anon_world_readable_only=YES` | Anonymous users can only read world-readable files |
| `xferlog_enable=YES` | Log all file transfers |

> **Note:** `tcp_wrappers=YES` was removed from this config. On AlmaLinux 9, vsftpd no longer supports tcp_wrappers and enabling it causes a `500` error on connection.

Restart and confirm the config took effect:

```bash
systemctl restart vsftpd
ss -ltn
```

```
LISTEN  0  32  0.0.0.0:21  0.0.0.0:*
```

After restarting with `listen=YES` and `listen_ipv6=NO`, vsftpd now binds only to IPv4 (`0.0.0.0:21`), which is the desired behavior.

#### Troubleshooting - FTP Returns 500 Error on Connection

After the initial install, connecting to the FTP server returned an error:

```
curl: (8) Got a 500 ftp-server response when 220 was expected
```

A 500 error at the initial connection is caused by a configuration problem at startup. On AlmaLinux 9, `tcp_wrappers` support was removed from vsftpd, but the default config still includes `tcp_wrappers=YES`. Removing that line from `/etc/vsftpd/vsftpd.conf` and restarting the service resolved the issue.

After the fix, from Server 2:

```
[root@server2 ~]# curl ftp://192.168.56.106/
drwxr-xr-x    2 0  0  6 Apr 09 18:46 pub
```

## Part 7 - Set Up DNF Repositories on Server 2 (Optional)

This step configures Server 2 to use Server 1's FTP as a local package repository instead of the internet. This is optional for the PXE lab series but demonstrates how the FTP server can serve as an offline package source for internal machines.

### Remove default repos on Server 2

```bash
cd /etc/yum.repos.d
mv * ~/
ls /etc/yum.repos.d   # should be empty
```

### Create the FTP repo file

```bash
vi /etc/yum.repos.d/ftp.repo
```

```ini
[centos72]
name=CentOS 7.2 - FTP
baseurl=ftp://server1.example.vm/pub/centos72/
enabled=1
gpgcheck=0

[almalinux9-minimal]
name=AlmaLinux 9 Minimal - FTP
baseurl=ftp://server1.example.vm/pub/almalinux9/Minimal/
enabled=1
gpgcheck=0
```

Note the repo file uses `server1.example.vm` by hostname - this only works because DNS ([[PXE Lab 1 - Configuring BIND DNS|Lab 1]]) and DHCP ([[PXE Lab 2 - Configuring a DHCP Server|Lab 2]]) are in place.

### Test the repos

```bash
dnf clean all
dnf install -y bash-completion
```

```
CentOS 7.2 - FTP              14 MB/s | 4.6 MB     00:00
AlmaLinux 9 Minimal - FTP      9.4 MB/s | 1.6 MB     00:00

Installing:
 bash-completion    noarch  1:2.11-5.el9  almalinux9-minimal  291 k

Complete!
```

The repo names `CentOS 7.2 - FTP` and `AlmaLinux 9 Minimal - FTP` at the top of the output confirm packages are being pulled from Server 1's FTP rather than the internet.

## Part 3 — Configure vsftpd

The config file is at `/etc/vsftpd/vsftpd.conf`. Edit it to allow anonymous read-only
access and listen on IPv4 only.

```bash
vi /etc/vsftpd/vsftpd.conf
```

Replace the contents with the following (removing comments for clarity):

```
anonymous_enable=YES
local_enable=NO
write_enable=NO
local_umask=022
dirmessage_enable=YES
xferlog_enable=YES
connect_from_port_20=YES
xferlog_std_format=YES
listen=YES
listen_ipv6=NO
pam_service_name=vsftpd
userlist_enable=YES
tcp_wrappers=YES
anon_world_readable_only=YES
```

| Setting | Meaning |
|---|---|
| `anonymous_enable=YES` | Allow anonymous logins (no password) |
| `local_enable=NO` | Block system user logins |
| `write_enable=NO` | No uploads or directory creation |
| `listen=YES` | Run in standalone mode on IPv4 |
| `listen_ipv6=NO` | Disable IPv6 listener |
| `anon_world_readable_only=YES` | Anonymous users can only read world-readable files |
| `xferlog_enable=YES` | Log all transfers |

## Troubleshooting

| Problem | Check |
|---|---|
| Port 21 not listening | `systemctl status vsftpd` — check for config errors |
| Browser shows empty pub directory | Files not world-readable — run `chmod -R o+r /var/ftp/pub/` |
| `mount: no medium found` | ISO not attached in VirtualBox storage settings |
| Not enough disk space | Expand disk or attach a second virtual disk to Server 1 |
| Server 2 DNS gets overwritten after adding NAT | Confirm `PEERDNS=no` is set in `ifcfg-enp0s3` on Server 2 |
| Server 2 can't reach internet | Check `enp0s3` is up: `nmcli connection up enp0s3` |
| DNF repo errors for AlmaLinux 9 | Confirm both subdirs exist: `ls /var/ftp/pub/almalinux9/BaseOS` and `ls /var/ftp/pub/almalinux9/AppStream` |
